# 验收：画面变化≠转向推进

先检查原始母版与生成图，再检查登记到144px的纯旋转。角度标签只表示目标，差值/哈希/文件数不能证明真实朝向。所有结论分 `passed`、`needs-repair`、`uncertain`；后两者均不能进入Q弹成品。

## 1. 无角度提示的相邻对检查

`audit-rotation.mjs create` 输出所有24对相邻图（包含F24→F01）及3组相同图对照，随机顺序、不展示帧号和目标角。图片共用登记、尺度与背景，不能单独居中某一帧。

检查者只看 `images/` 与 `answers.template.json`，先不读 `answer-key.json`；已有独立审阅者/获授权的子代理时由其完成，避免生成者被目标角引导。不支持独立审阅时仍逐图检查，但应诚实注明同一检查者知道制作上下文，不能谎称独立盲检。不需要为了这项检查自动新建用户任务。

每对记录：

- `verdict`：clear-rotation / same-heading / uncertain / identity-drift。
- `headGeometry`：头颅、脸颊、鼻耳或固定头饰投影/遮挡的实际变化。不能只说头发颜色或纹理变了。
- `torsoGeometry`：身体侧别、肩袖、手脚、胸饰或裙摆等实际投影/遮挡变化。胸被长发挡住时选可见结构；全部不可辨就uncertain，不能编造。
- `identityStable`：是否还是同一表情、姿态、衣服和配饰。

完成答案后才核对键。三个同图对照应识别为same-heading；真实相邻对需要clear-rotation和稳定身份。检查脚本只核对记录完整性、对照与摘要，不是视觉算法。

## 2. 顺序三帧检查：方向和步幅

相邻对有变化，仍可能倒转或忽快忽慢。查看 `rotation-windows/window-Fxx.png` 的前一帧→当前帧→后一帧，特别检查近侧、近背和首尾。

`rotation-review.json.steps` 对24个前进步分别记录：

- `progress`：forward / hold / reverse / uncertain。
- `stepSize`：small-even / hold / jump / uncertain。
- `headBodyCoupled`、`appearanceStable`，及描述实际结构的 `observation`。

判定small-even应有两侧邻步的对比：不能“前一步几乎没动，下一步突然跨大段”；不要求从像素反推精确15°。头和身体共转，手脚姿势不表演，长发不自行摆动。一个方向有不同画法不能当成多个角度。

每一张中间帧应落在其前后端点之间，不能复制端点、越界、倒退。末尾F23→F24→F01→F02使用同样标准，不能用重复正面延时缝合。未能辨认的具体段写明，禁止泛写“整体流畅”。

## 3. 整圈与身份

检查144px原尺寸与整数倍最近邻放大预览，以及实际动画播放：

- 头大身短、短脚收拢、双手在髋侧，神态与母版一致；不能统一甜笑。
- 正/侧/背完整，速度观感近似均匀，无停住后跳变、反向、独立扭头。
- 头大小、坐姿、衣饰数量与人物自身左右稳定；长发与配饰只发生视角遮挡。
- 中性序列无预制Q弹，固定转轴与底线；像素块清楚、整圈色板一致。

有实际连续播放能力时观察数圈。工具只提供静态截图时，记录“播放采样”和实际观察的帧，配合逐帧窗口；不能根据播放计时器声称连续看完了三圈。不能只看接触表就声称观察过动画。

只有上述层次全部通过，才把当前摘要绑定的 `rotation-review.json.status` 改为passed。替换任何源帧后重做prepare及相关完整检查，旧记录失效。工具通过不代表视觉通过。

## 4. Q弹成品检查

纯旋转通过后再看 `spin-144.gif`。高度最高与最低之比1:2/3、宽度1:1.5，整圈两次，底线固定；明显但无裁切、轴线摇摆、色板闪烁。检查深浅背景无白框、棋盘和上一帧残影。

实际完成后才将 `validation.json.visualReview` 写passed，并另记观察文件、证据、问题区间及结论。原画失败回到原画；轴线问题修登记；仅缩放问题才调Q弹。禁止批量填true或根据文件存在推断质量。
